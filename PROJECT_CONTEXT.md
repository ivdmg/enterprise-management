## Продукт и текущий источник

Enterprise Management / Smart Enterprise Hub. React 19 + TypeScript + Vite 8, FastAPI + SQLAlchemy asyncio + PostgreSQL в Neon. Фронтенд обращается к настоящему API, USE_MOCKS=false. В production фронтенд собирается Dockerfile и обслуживается FastAPI по одному адресу. База и Google Drive общие для компьютера, ноутбука и Render при переносе тех же настроек.

## Реализация

- backend/app/services/customer_tenders.py: чтение двух листов, объединённые двухстрочные заголовки реестра, три повторяющихся блока мониторинга, нормализация внутреннего номера, ошибки формул, пустые суммы.
- backend/app/services/template_parser.py: распознавание структуры заказчика перед прежними шаблонами.
- backend/app/services/drive_sync.py: ограничение живого источника через GOOGLE_DRIVE_SOURCE_FILE_ID, транзакционная замена данных документа, повторный импорт без дублей, обработка удаления строк.
- TenderProject.custom_attributes: исходные значения обоих листов, колонки, номера исходных строк, предупреждения; схема БД для адаптации не менялась.
- GET /api/v1/customer-tenders: записи только организации авторизованного пользователя.
- frontend/src/features/dashboard/CustomerTendersTab.tsx: сводка, полный реестр и ежедневный мониторинг с поиском и ссылкой на источник.
- Навигация App.tsx/Header.tsx показывает только сводку, реестр, мониторинг и Google Drive. Прежние разделы сохранены в коде для будущих источников, но скрыты.
- Не выводите неподтверждённые кассу, задолженности, оплаты или штрафы из старых модулей: текущий источник этих фактов не даёт. Отсутствие суммы не равно нулю.

## Запуск и ограничения

См. LAPTOP_SETUP.md. Секреты и доступ к той же организации переносятся отдельно: backend/.env, backend/credentials.json, .demo/access.json. Не пересоздавайте компанию и не запускайте scripts.setup_demo при переносе существующей базы. ALLOW_REGISTRATION=false для демостенда. Google Drive привязан к GOOGLE_DRIVE_COMPANY_ID.

Рекомендуется один работающий экземпляр синхронизации: после запуска Render не держать одновременно локальные серверы на компьютере и ноутбуке с той же базой. Обычные пользовательские браузеры этого ограничения не имеют. Статус фоновой синхронизации хранится в памяти процесса. Источники остаются на Drive; удаление целого документа не удаляет автоматически импортированные бизнес-данные. Удаление строк внутри документа обрабатывается.

Сервисный аккаунт читает существующие документы, но не имеет квоты создавать новые файлы в личном Drive. Для загрузки новых источников используйте Google-аккаунт владельца. Сам импорт и синхронизация работают через существующий сервисный ключ.
