# Развёртывание рабочей версии

Рабочая ветка — `main`. Для обоих вариантов используется `npm run build`, который собирает интерфейс для настоящего API.

## Render и существующий Neon

1. В Render подключите GitHub-репозиторий и выберите ветку `main`. Для нового Web Service укажите Docker, корень репозитория, `./Dockerfile` и проверку `/health`. Если сервис уже существует, используйте его настройки и адрес.
2. В Environment задайте `DATABASE_URL`, `JWT_SECRET`, `GOOGLE_SERVICE_ACCOUNT_JSON`, `GOOGLE_DRIVE_ROOT_FOLDER_ID`, `GOOGLE_DRIVE_COMPANY_ID` и `GOOGLE_DRIVE_SOURCE_FILE_ID`. Для показа с выданной учётной записью используйте `ALLOW_REGISTRATION=false`. Также задайте `DEBUG=false` и `GOOGLE_DRIVE_MOCK=false`. Переносите значения через Environment из локального файла настроек.
3. Docker применяет миграции перед запуском. Проверьте `/health`, страницу входа и вход существующей учётной записью. Оставьте один экземпляр с фоновой синхронизацией на эту базу и папку Drive.

React и FastAPI доступны по одному адресу Render. На Free сервис засыпает при простое, а загруженные на локальный диск файлы исчезают при перезапуске. Для демо с локальными вложениями учитывайте это ограничение. Исходники Drive и данные Neon хранятся отдельно.

## Vercel как отдельный фронтенд

1. Поднимите FastAPI на Render и проверьте его адрес. В Vercel подключите репозиторий, выберите `main` как Production Branch и `frontend` как Root Directory. Vercel использует `frontend/vercel.json`.
2. В Vercel задайте `VITE_API_ORIGIN=https://<сервис>.onrender.com`. В Render добавьте точный HTTPS-адрес фронтенда в `CORS_ORIGINS`. В переменные `VITE_*` помещайте только публичные значения.
3. Проверьте вход через публичный адрес Vercel. Тариф Hobby предназначен для личных некоммерческих проектов. Для коммерческого проекта потребуется подходящий тариф.

Корневой `vercel.json` описывает прежний вариант с FastAPI в Vercel Functions. Для текущей фоновой синхронизации и локальных вложений используйте Docker-сервис.
