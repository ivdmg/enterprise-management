# Первое демо заказчику

Фронтенд React собран и обслуживается FastAPI по одному адресу. Данные хранятся в уже настроенном Neon PostgreSQL из локального `backend/.env`. Подключение к Google Drive использует ваш сервисный аккаунт. Моковые данные фронтенда отключены, числовые подстановки на сводке удалены.

## Доступ

- Локально: http://127.0.0.1:8080
- Текущий временный внешний адрес сохранён в `.demo/public-url.txt`.
- Два пользователя одной организации: `demo-admin@example.com` и `demo-customer@example.com`. Их сгенерированные пароли находятся только в `.demo/access.json`.
- Регистрация отключена. Google Drive привязан только к демонстрационной организации через `GOOGLE_DRIVE_COMPANY_ID`.

Временный внешний адрес работает через localhost.run: компьютер, приложение и SSH-туннель должны оставаться включёнными. Бесплатный адрес может меняться и не предназначен для постоянного хостинга. Если ссылка перестала работать, запустите новый туннель командой ниже.

```powershell
.\start-demo.ps1 -Share
```

Адрес HTTPS появится в терминале. Не закрывайте этот терминал во время показа. Для остановки сервера используйте `.\stop-demo.ps1`; для остановки туннеля — Ctrl+C в его терминале.

Загрузите все пять файлов прямо в корень подключённой папки через ваш Google-аккаунт. Можно использовать созданные тематические подпапки, но для первого демо это необязательно. После загрузки нажмите «Синхронизировать Диск» в приложении. Первая загрузка и пересчёт рисков могут занять около минуты из-за запросов к удалённой базе. Далее откройте сводку и основные вкладки.

Сервисные аккаунты Google не имеют собственной квоты для создания обычных файлов в личном Google Drive. Реальная попытка загрузки через имеющийся ключ вернула `403 storageQuotaExceeded`. Поэтому исходники загружает владелец Google-аккаунта. Чтение, скачивание и экспорт уже существующих документов работают через сервисный аккаунт. Для загрузки новых документов из самой платформы в будущем потребуется OAuth от имени пользователя либо Google Workspace Shared Drive.

## Сценарий показа на 5 минут

1. Войти в приложение и синхронизировать загруженные файлы. Показать сводку, контракты, финансы, снабжение и задачи.
2. На вкладке «Файлы и Google Диск» открыть реестр контрактов по ссылке на исходный документ.
3. В первой строке данных изменить `Оплачено_Заказчиком_Руб` в ячейке **J2** с исходных 20 000 000 на **21 000 000**. Дождаться сохранения на Диске.
4. Вернуться в приложение и нажать «Синхронизировать Диск». Дебиторская задолженность по этому контракту уменьшится на **1 000 000 ₽**. Данные активной вкладки загрузятся заново.
5. Открыть файл ДДС, изменить сумму поступления в **E2** на сумму больше исходной на **500 000 ₽**. Сохранить и синхронизировать: свободная касса увеличится на **500 000 ₽**.
6. Показать повторную синхронизацию без правок: суммы и количество записей сохраняются, файлы помечаются как «без изменений».

Для показа именно **Google Таблиц** откройте один `.xlsx` и выберите «Файл → Сохранить как Google Таблицы». Сохраните нативную таблицу в подключённой папке. Исходный `.xlsx` переместите за пределы отслеживаемой папки **до первого импорта**, чтобы два документа не представляли один и тот же реестр. Не меняйте названия колонок и оставьте таблицу данных на первой вкладке. Синхронизация экспортирует Google Таблицу в XLSX и использует тот же парсер. Обычный `.xlsx` также можно редактировать прямо в интерфейсе Google Таблиц без конвертации.

После первого импорта не заменяйте источник отдельной копией с другим ID: источник отслеживается по ID документа. Для изменения используйте тот же документ. Удаление строк внутри него поддерживается. Удаление всего файла с Google Drive автоматически не удаляет уже импортированные бизнес-данные.

## Что проверено

- Сборка TypeScript/Vite и линтер: ошибок нет; у линтера остались предупреждения существующего кода.
- Миграции PostgreSQL применены; `alembic check` не обнаруживает расхождения схемы и моделей.
- Внешний HTTPS: HTML приложения, вход, профиль, все основные API и ручная живая синхронизация проверены HTTP-запросами.
- Интеграционный тест с временной организацией в PostgreSQL: 113 строк из пяти документов, пропуск неизменённых файлов, обновление и удаление строк, восстановление после повреждённого документа, отсутствие удвоения сумм.
- Отдельные тесты реального протокола Google: разрешение названий папок в ID, пагинация, экспорт нативной Google Таблицы, запрет скрытого перехода в моки при отсутствии ключа.

В живой папке на момент проверки документов нет: полный пользовательский сценарий с Google Drive нужно завершить после загрузки исходников. Реальное редактирование нативной Google Таблицы проверено тестом API-клиента, но не выполнено в вашем Google-аккаунте. Автоматизация Chrome была остановлена инструментом из-за невозможности надёжно определить URL; визуальная проверка приложения в браузере не выполнена.

## Постоянный бесплатный демостенд на Render

Для следующего шага выбран **Render Web Service (Docker) + существующий Neon PostgreSQL**. Отдельно размещать фронтенд не требуется. В репозитории есть `Dockerfile`, `.dockerignore` и `render.yaml`. Сборка React выполняется в Docker, миграции запускаются перед стартом FastAPI.

1. Войти в Render и создать Blueprint из репозитория `ivdmg/enterprise-management`, выбрав ветку с изменениями демо.
2. Указать секреты из локального **`.demo/render.env`**. Этот файл содержит ключ Google и строку подключения к базе; он исключён из Git и Docker. Вставлять его нужно только в Environment сервиса Render.
3. Нажать Deploy. После успешного `/health` открыть адрес `https://...onrender.com` и войти теми же демопользователями: база остаётся той же.

На Render Free сервис засыпает после 15 минут без запросов и просыпается примерно за минуту. Перед показом откройте ссылку заранее. Фоновый опрос Google Drive работает, пока процесс сервиса запущен; после пробуждения используйте ручную синхронизацию. Локальные копии файлов на бесплатном Render непостоянны, но исходники остаются на Google Drive, а разобранные данные — в Neon.

Кнопка синхронизации запускает фоновую задачу и опрашивает её статус короткими запросами. Длительная обработка Google Drive не держит одно HTTP-соединение открытым и не зависит от тайм-аута прокси. Статус выполняющейся задачи хранится в памяти одного процесса, поэтому для демо используется один процесс Uvicorn.

Деплой на Render не выполнен: в окружении нет авторизованного аккаунта/токена Render. Действующий внешний показ организован через временный SSH-туннель. Безопасно подготовленная конфигурация для Render готова к применению после входа в аккаунт.

Справка: https://render.com/docs/free и https://localhost.run/docs/faq/
