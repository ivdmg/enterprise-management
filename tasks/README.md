# Бэклог централизованной платформы

Цель первого выпуска — доказать сквозную работу двух независимых компаний и подготовить повторяемое подключение до пяти. Решения и границы в [проектном пакете](../docs/08_platform_mvp/README.md).

| Порядок | Что отдавать агентам параллельно |
| --- | --- |
| 1 | BE-00 фиксирует контракты, QA-01 готовит тестовый стенд и фикстуры. FE-01 и FE-02 проектируют экраны и состояния по проектному пакету, интеграция после контракта |
| 2 | После BE-00 отдельно выполнять BE-01/02, BE-03/04 и BE-05. Один ответственный за порядок и объединение Alembic-ревизий, владельцы веток согласуют изменения общих зависимостей |
| 3 | FE-01 и FE-02 подключают API по мере готовности. BE-06 собирает сквозные сценарии после BE-02/03/04/05 |
| 4 | QA-02 и QA-03 принимают сборку. Исправления возвращаются владельцам соответствующего потока |

- [Бэкенд](backend.md)
- [Фронтенд](frontend.md)
- [Приёмка](qa.md)

Общие правила для агентов. Сначала прочитать PROJECT_CONTEXT.md и LAPTOP_SETUP.md. Использовать отдельную БД и каталог/бакет для тестов. Рабочую базу и источники демо не менять. Синтетические фикстуры используются только в испытаниях. Передавать результат с командами проверки и перечнем затронутых контрактов. Бэклог ограничен кодом, локальными проверками и приёмкой.
