### Локальный запуск фазы 2

Из корня демо-worktree, Python 3.12 и Node.js 24:

```sh
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -r backend/showcase/requirements.txt
npm --prefix frontend ci
npm --prefix frontend run build:showcase
cd backend
../.venv/bin/python -m uvicorn showcase.main:app --host 127.0.0.1 --port 8011
```

Открыть `http://127.0.0.1:8011/`. После правок фронтенда повторить `npm --prefix frontend run build:showcase` из корня. `/health` возвращает `source: synthetic`. Для локального прогона нужны только исходники и зависимости. `DEMO.md`, `LAPTOP_SETUP.md`, `render.yaml`, обычный `Dockerfile` и команда `npm run dev` описывают другие режимы проекта.

Для сборки под отдельный сервис использовать `docker build -f Dockerfile.showcase -t enterprise-hub-showcase .`. Корень демо-папки Google Drive уже создан владельцем. Подключение, создание структуры внутри папки и заполнение синтетическими таблицами входят в фазу 3.

**Проверка фазы 1.** Собраны обычный и демо-фронтенд. FastAPI запущен с очищенным окружением. В чистом профиле Chromium открыты обзор и шесть разделов, проверены ответы демо-API и отсутствие внешних запросов при загрузке. ### Источники и конфигурация

| Папка | Google Таблица | Листы | Переменная ID |
| --- | --- | --- | --- |
| Команда | Документы сотрудников | Документы сотрудников | `SHOWCASE_TEAM_SHEET_ID` |
| Финансы | Реестр платежей | Платежи | `SHOWCASE_FINANCE_SHEET_ID` |
| Операции | Контракты и операции | Реестр контрактов, Ежедневный мониторинг, Задачи, Сигналы, Смены | `SHOWCASE_OPERATIONS_SHEET_ID` |
| Запасы | Реестр закупок и поставок | Поставки | `SHOWCASE_STOCK_SHEET_ID` |

Для подключения нужны Google Drive API и Google Sheets API в проекте демо-сервисного аккаунта. На сервере задайте `SHOWCASE_GOOGLE_CREDENTIALS_JSON` через секрет окружения или `SHOWCASE_GOOGLE_CREDENTIALS_FILE` как путь к закрытому файлу вне репозитория. Идентификаторы таблиц берутся из отрезка между `/d/` и `/edit` в адресе каждой книги. Дополнительные файлы дерева задаются через `SHOWCASE_CATALOG_FILE_IDS` через запятую. Ярлыки игнорируются. Корень фиксирован на стороне демо-сервера. Дерево отдаёт названия и внутренние идентификаторы. Ссылки в шапках и карточках строятся для настроенных таблиц после проверки их принадлежности демо-корню. При открытии таблицы действуют права Google Drive.

В демо-реестре сохранена связь по «вн.№». Загрузчик также понимает прежнее имя «Реест Ольга» до переименования в «Реестр контрактов». Заголовки и состав полей компактной демо-схемы определены в `backend/showcase/tables.py`. Документы используют заголовки «Сотрудник», «Документ», «Действует до». Дата принимается в ISO-формате или как дата Google Таблиц. «Истекает» означает срок до 30 дней включительно. Пустой срок помечает документ как отсутствующий.

Для живого прогона после выдачи доступа:

1. Запустите демо локально и дождитесь `source: drive`. Откройте документы и дерево без входа.
2. Измените `C4` листа «Документы сотрудников» на прошедшую дату, дождитесь следующего `refreshed_at` и проверьте «Просрочен». Верните исходную дату и дождитесь восстановления статуса.
3. Поместите отдельный синтетический файл из перечня `SHOWCASE_CATALOG_FILE_IDS` внутрь демо-корня. Проверьте его появление после очередного снимка и отсутствие ссылки на скачивание.
4. Временно измените заголовок `C3`, проверьте `source: snapshot` и `issue: schema`, верните заголовок. Для проверки сетевой ошибки остановите доступ тестового экземпляра к Google API, проверьте сохранение снимка, затем перезапустите его и проверьте `source: synthetic`. После восстановления доступа должен вернуться `source: drive`.

Проверенный адрес локального прогона 22 ноября 2026 года — `http://127.0.0.1:8013/`, активный источник — `synthetic`. Используется команда локального запуска из фазы 2 с портом 8013. При подключённых Google API `drive` означает последний успешный ответ Google, `snapshot` — сохранённый результат после ошибки, `synthetic` — локальный набор. `issue` различает схему (`schema`) и недоступность (`unavailable`). Обновление запускается фоново по запросу, поэтому после правки дождитесь нового `refreshed_at`.

## Универсальный шаблон источников

Четыре книги распределены по владельцам данных: «Команда» хранит документы, «Финансы» — платежи, «Операции» — контракты, задачи, сигналы и смены, «Запасы» — счета и поставки. Одна запись занимает одну строку. Код записи остаётся стабильным при сортировке. Договор связан с мониторингом по «вн.№», с оплатами по коду контракта, с задачами по коду объекта и номеру договора. Для поставок и смен название объекта должно совпадать с реестром. Вводите даты как даты Google Таблиц или ГГГГ-ММ-ДД, суммы — числами. Функция `template_tables()` в `backend/showcase/tables.py` генерирует примеры с русскими заголовками и понятными значениями этапов, ролей и статусов смен.

Для базового подключения предприятие заполняет стандартные книги. При отраслевой настройке можно подключить существующие колонки через маппинг или добавить адаптер. В оформлении используются тёмно-зелёная закреплённая шапка и чередующиеся светлые строки.

**Финансы и сигналы.** Дебиторка показывает положительный остаток «Выполнено» минус оплаты по заказчику. Кредиторка суммирует счета со статусом «Счет на оплате» по поставщику. Период графика относится к движению денег, списки показывают текущие остатки. Плитка «Штрафы и неустойки» складывает поле «Оценка потерь, ₽» открытых сигналов о нарушении срока. Поле «Расчёт пени» в проектах читается отдельно. В резервном наборе пример оценки по просроченному незавершённому договору равен 1% суммы договора. Дни просрочки пересчитываются из даты договора.

**Проверка правок витрины.** Шесть изолированных тестов импорта/API пройдены. Chromium и WebKit прошли матрицу из семи размеров от 375×667 до 1920×1080, включая прокрутку с открытым сайдбаром. Переходы в таблицу и строку проверены через тестовый снимок на 375, 1280 и 1920 px. Восемь листов из четырёх локальных книг прочитаны парсером. Четыре существующие книги обновлены через Google Drive. Все восемь листов считаны обратно и успешно проверены демо-парсером, включая 12 контрактов, 54 задачи и 8 смен. Проверка фонового чтения от отдельного сервисного аккаунта остаётся открытой.
