## Что берём из демо

React/Vite, FastAPI, SQLAlchemy, Alembic, PostgreSQL и работающий импорт двух листов. Документы в разделах 01–07 описывают исходную цель, доменные модели и старые контракты. При расхождении опираемся на PROJECT_CONTEXT.md и код. Например, старый инфраструктурный план описывает другой фронтенд и нулевой бюджет, а исторический API предусматривает самостоятельную регистрацию и создание сотрудников админом компании.

В коде JWT сверяется с активной записью пользователя и его компанией. Email уникален глобально. API компании умеет создать сотрудника с начальным паролем, но этот путь противоречит новому процессу выдачи доступа. Интерфейс сохраняет сессию и выбранную визуальную роль в localStorage. Серверные права следует проверять независимо от интерфейса.

FastAPI раздаёт React из одного Docker-образа. Render настроен на запуск миграций при старте, Neon хранит данные, вложения используют локальное хранилище. Google Drive привязан к глобальным настройкам одной компании, планировщик стартует вместе с API, статус и блокировка синхронизации живут в процессе. /health сообщает о работе приложения без проверки успешности импорта. Это выводы по репозиторию, доступность живого демо отдельно не проверялась.

## Граница первой версии

Общий продукт с разными наборами разделов и источников. Два кабинета с разными полномочиями. Закрытое подключение через поддержку. Отдельная очередь фоновых заданий на PostgreSQL, без внешнего брокера. Пилот на двух изолированных синтетических компаниях перед подключением новых реальных клиентов. Следующий этап — до пяти компаний по одному повторяемому процессу. Развёртывание рассматривается как вариант для будущего решения.
