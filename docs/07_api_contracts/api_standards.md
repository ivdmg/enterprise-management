# Стандарты и соглашения API (RESTful API Standards)
## Проект: Smart Enterprise Hub (MVP)

Данный документ регламентирует общие правила построения HTTP REST API: форматы ответов, авторизацию, обработку ошибок, пагинацию и версионирование. Все эндпоинты бэкенда на FastAPI должны строго следовать этим стандартам.

---

## 1. Базовые принципы

1. **Базовый URL**: Все маршруты имеют префикс `/api/v1`.
2. **Формат данных**: `application/json; charset=utf-8` для всех тел запросов и ответов (кроме бинарной загрузки файлов `multipart/form-data`).
3. **Именование полей**: Все JSON-ключи и query-параметры пишутся в нотации `snake_case`.
4. **Статусы ответов HTTP**:
   - `200 OK`: Успешная выборка или обновление.
   - `201 Created`: Успешное создание ресурса (компании, файла, задачи).
   - `204 No Content`: Успешное удаление без тела ответа.
   - `400 Bad Request`: Ошибка валидации входных данных.
   - `401 Unauthorized`: Отсутствует или истек JWT токен.
   - `403 Forbidden`: Недостаточно прав роли пользователя.
   - `404 Not Found`: Запрашиваемый ресурс не найден в рамках текущей компании.
   - `409 Conflict`: Конфликт данных (например, загрузка дубликата файла с тем же SHA-256).
   - `422 Unprocessable Entity`: Ошибка схемы Pydantic.
   - `500 Internal Server Error`: Непредвиденный внутренний сбой сервера.

---

## 2. Единый формат ответа (Standard Response Envelope)

Любой ответ сервера оборачивается в стандартный контейнер (Envelope):

### Успешный ответ (Success Response):
```json
{
  "success": true,
  "data": {
    "id": "b0000000-0000-0000-0000-000000000001",
    "project_name": "Строительство цеха №4",
    "contract_sum": 12500000.00
  },
  "error": null,
  "meta": {
    "timestamp": "2026-10-11T14:30:00Z"
  }
}
```

### Ответ со списком и пагинацией (List & Pagination):
```json
{
  "success": true,
  "data": [
    { "id": "uuid-1", "project_name": "Объект 1" },
    { "id": "uuid-2", "project_name": "Объект 2" }
  ],
  "error": null,
  "meta": {
    "page": 1,
    "limit": 20,
    "total_items": 142,
    "total_pages": 8,
    "timestamp": "2026-10-11T14:30:00Z"
  }
}
```

### Ответ с ошибкой (Error Response):
```json
{
  "success": false,
  "data": null,
  "error": {
    "code": "FILE_DUPLICATE",
    "message": "Файл с идентичным содержимым уже был загружен ранее",
    "details": {
      "existing_file_id": "a1b2c3d4-0000-0000-0000-000000000001",
      "uploaded_at": "2026-10-10T11:20:00Z"
    }
  },
  "meta": {
    "timestamp": "2026-10-11T14:30:00Z"
  }
}
```

## 3. Аутентификация и авторизация (JWT Bearer)

1. Аутентификация осуществляется через HTTP-заголовок:
   ```http
   Authorization: Bearer <access_token>
   ```
2. Полезная нагрузка токена (`Payload`):
   ```json
   {
     "sub": "user-uuid",
     "company_id": "company-uuid",
     "role": "admin",
     "exp": 1760200000
   }
   ```
3. Все эндпоинты бэкенда через FastAPI Dependency Injection (`Depends(get_current_user)`) автоматически извлекают `company_id` и изолируют доступ к данным на уровне SQL-запроса.

---

## 4. Пагинация и фильтрация

Для всех эндпоинтов со списками (`GET /files`, `GET /projects`, `GET /alerts`) поддерживаются стандартные параметры:
- `page`: Номер страницы (по умолчанию `1`).
- `limit`: Количество записей на странице (по умолчанию `20`, максимум `100`).
- `sort_by`: Имя поля сортировки (по умолчанию `created_at` или `operation_date`).
- `order`: Направление сортировки (`asc` или `desc`).
- `search`: Текстовый поиск по ключевым полям (название проекта, контрагент, имя сотрудника).
