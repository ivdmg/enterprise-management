# Спецификация функциональных требований (Functional Requirements)
## Проект: Smart Enterprise Hub (MVP)

Данный документ фиксирует исчерпывающий перечень функциональных требований (FR) к платформе операционного управления предприятием на базе гибридного парсинга Excel-документов. Документ служит первоисточником для системных разработчиков, QA-инженеров и ИИ-агентов при реализации кодовой базы.

---

## 1. Ролевая модель и акторы системы

| Роль | Описание | Основные права и зоны ответственности |
| :--- | :--- | :--- |
| **Собственник / Генеральный директор (Executive)** | Главный потребитель аналитики | Просмотр главного экрана «Где горит?», получение сводки в Telegram, утверждение критических решений, чтение всех доменов. |
| **Операционный директор / Руководитель проектов (Manager)** | Управление проектами и подрядчиками | Загрузка реестров СМР/тендеров, подтверждение маппинга колонок, контроль дедлайнов и штрафов, закрытие этапов. |
| **Финансовый менеджер / Бухгалтер (Finance)** | Контроль денежных потоков и ФОТ | Загрузка отчетов о движении ДС, взаиморасчетов с контрагентами, реестров зарплат, проверка кассовых разрывов. |
| **Администратор компании (Company Admin)** | Управление организацией | Настройка юрлиц компании, приглашение сотрудников, управление интеграцией с Telegram-ботом, аудит файлов. |

---

## 2. Модульная спецификация требований

### Блок 1: Мультиарендность, Аутентификация и Доступ (FR-AUTH)

- **FR-AUTH-1 (Изоляция тенантов)**: Системная модель данных должна быть строго мультиарендной. Все ключевые таблицы содержат обязательное поле `company_id`. Пользователь одной компании ни при каких условиях не может получить доступ к файлам или данным другой компании.
- **FR-AUTH-2 (Регистрация и онбординг)**:
  - Регистрация пользователя с созданием профиля первичной компании (Название, ИНН, часовой пояс).
  - Первичный пользователь получает роль `admin`.
- **FR-AUTH-3 (Аутентификация)**:
  - Авторизация по паре Email + Пароль с выдачей JWT токенов: `access_token` (время жизни 60 минут) и `refresh_token` (время жизни 14 дней).
  - Хеширование паролей с использованием надежного алгоритма Argon2id или Bcrypt.
- **FR-AUTH-4 (Управление пользователями)**:
  - Администратор может создавать/приглашать коллег в рамках своей компании с назначением ролей (`admin`, `manager`, `viewer`).
  - Привязка Telegram-аккаунта пользователя через уникальный одноразовый deep-link код (например, `/start link_token_xyz`).

---

### Блок 2: Загрузка файлов и предварительная обработка (FR-INGEST)

- **FR-INGEST-1 (Поддерживаемые форматы)**: Загрузка файлов электронных таблиц форматов `.xlsx`, `.xls`, `.csv`. Ограничение размера файла для MVP: до **25 МБ**.
- **FR-INGEST-2 (Интерфейс Drag-and-Drop)**: Пользовательский интерфейс должен поддерживать пакетное перетаскивание файлов с визуализацией прогресса загрузки и валидации.
- **FR-INGEST-3 (Дедупликация и хеширование)**: При загрузке сервер вычисляет хеш SHA-256 содержимого файла. Если файл с идентичным хешем уже загружен в рамках данной компании, система предупреждает пользователя о дубликате и предлагает либо обновить существующую запись, либо отменить операцию.
- **FR-INGEST-4 (Изолированное хранение)**: Файлы сохраняются в изолированную структуру директорий с уникальным UUID-именем. В базе сохраняется исходное название файла, размер, дата загрузки и ID загрузившего пользователя.
- **FR-INGEST-5 (Структурная нормализация raw-матрицы)**:
  - Детекция и развертывание объединенных ячеек (`merged cells`) с каскадным наследованием заголовков верхнего уровня.
  - Очистка пустых строк, пустых колонок и служебных мета-шапок (первые N декоративных строк).
  - Детекция реальной шапки таблицы по плотности текстовых ячеек и типов нижележащих данных.

---

### Блок 3: Гибридный конвейер парсинга и кэширования шаблонов (FR-PARSE)

- **FR-PARSE-1 (Профилирование типов)**:
  - Автоматическое распознавание колонок с денежными суммами (очистка от `₽`, `$`, `руб.`, неразрывных пробелов, приведение к типу `numeric/float`).
  - Распознавание дат в форматах ISO, `ДД.ММ.ГГГГ`, `ДД/ММ/ГГ` и приведение к формату `YYYY-MM-DD`.
  - Отделение строк промежуточных и финальных итогов («Итого», «Всего», «В т.ч. НДС») от основных учетных записей.
- **FR-PARSE-2 (Кэш шаблонов компании / Fingerprint)**:
  - Система вычисляет отпечаток (хеш нормализованных заголовков колонок листа).
  - При совпадении с ранее сохраненным шаблоном компании этап вызова ИИ пропускается, и маппинг применяется мгновенно с 100% уверенностью.
- **FR-PARSE-3 (Семантический AI-маппинг)**:
  - Если шаблон не найден в кэше, сервер формирует компактный JSON (список колонок + 2 строки обезличенных примеров данных) и обращается к легковесному LLM API (Google Gemini 1.5 Flash / DeepSeek V3).
  - Модель возвращает сопоставление столбцов таблицы с канонической схемой и оценку уверенности (`confidence_score` от 0.0 до 1.0).
- **FR-PARSE-4 (Канонические домены)**: Парсер классифицирует таблицу по одному из 4 канонических бизнес-доменов:
  1. `production_tenders` (Тендеры, СМР, контракты, этапы).
  2. `cashflow_debt` (Движение ДС, счета, взаиморасчеты с контрагентами).
  3. `payroll_hr` (ФОТ, начисления, выплаты, сотрудники).
  4. `operational_tasks` (Реестры задач, предписания, налоговые дедлайны).

---

### Блок 4: UI подтверждения маппинга и ручная корректировка (FR-PREVIEW)

- **FR-PREVIEW-1 (Интерактивная шторка предпросмотра)**: После парсинга нового документа пользователю отображается окно предпросмотра:
  - Распознанный домен документа (с возможностью переключить вручную).
  - Таблица сопоставления колонок: `Исходная колонка из Excel` $\rightarrow$ `Каноническое поле системы`.
  - Цветовая индикация уверенности: зеленый (> 85%), желтый (50–85%), красный (< 50% / Не опознано).
- **FR-PREVIEW-2 (Ручная корректировка)**: Пользователь может в выпадающем списке изменить назначение любого поля или пометить колонку как «Игнорировать при импорте».
- **FR-PREVIEW-3 (Обучение кэша шаблонов)**: При подтверждении пользователем маппинга схема сохраняется в таблицу `file_templates`. При следующей загрузке файла с аналогичной структурой ручное подтверждение не требуется.

---

### Блок 5: Сводный аналитический дашборд руководителя (FR-DASH)

- **FR-DASH-1 (Экран первого взгляда / "Где горит?")**:
  - Карточки высокоуровневых KPI: Доступные ДС, Прогнозируемый дефицит, Портфель активных контрактов, Сумма выявленных финансовых рисков/штрафов.
  - Секция критических алертов с красной пульсирующей индикацией.
- **FR-DASH-2 (Вкладка «Финансы и касса»)**:
  - График динамики поступлений и списаний.
  - Календарь платежей на ближайшие 14 дней с фиксацией точек кассового разрыва.
  - Топ дебиторов и кредиторов компании.
- **FR-DASH-3 (Вкладка «Тендеры и производство»)**:
  - Реестр проектов со статусами выполнения (План / Факт закрытия по КС / Остаток).
  - Индикатор отклонения от графика (дней просрочки, отставание в рублях).
  - Ответственный куратор по каждому объекту.
- **FR-DASH-4 (Вкладка «ФОТ и персонал»)**:
  - Общий фонд оплаты труда за выбранный период.
  - Соотношение начисленных и фактически выплаченных средств.
  - Ближайшая плановая дата выплаты зарплаты/аванса.
- **FR-DASH-5 (Глобальные фильтры)**:
  - Фильтрация аналитики по юрлицу, датам (месяц, квартал, год, произвольный период) и статусу проектов.

---

### Блок 6: Движок выявления рисков и расчета финансовых последствий (FR-ALERT)

- **FR-ALERT-1 (Автоматический расчет штрафов и неустоек)**:
  - При обнаружении срыва дедлайна по контракту система производит расчет пени:
    $$\text{Штраф} = \text{Остаток обязательств} \times \frac{1}{300} \text{ Ключевой ставки ЦБ (или фикс. % из договора)} \times \text{Дней просрочки}$$
  - Расчет динамически обновляется каждый день до момента фактического закрытия этапа.
- **FR-ALERT-2 (Детекция кассового разрыва)**:
  - Автоматическое сопоставление остатка на расчетных счетах с плановыми списаниями по ФОТ, налогам и критическим платежам на горизонте N дней.
  - Генерация алерта при дефиците свободных средств.
- **FR-ALERT-3 (Уровни критичности событий)**:
  - `CRITICAL`: Просрочка этапа, кассовый разрыв < 7 дней, истечение банковской гарантии < 3 дней.
  - `WARNING`: Дедлайн сдачи работ через 3–5 дней, рост дебиторской задолженности выше нормы.
  - `INFO`: Успешное проведение платежа, подписание акта, загрузка нового реестра.
- **FR-ALERT-4 (Жизненный цикл алерта)**:
  - Статусы алерта: `active`, `acknowledged` (принят к сведению), `resolved` (устранен).
  - Возможность для менеджера прикрепить комментарий или назначить ответственного за устранение.

---

### Блок 7: Система доставки уведомлений (FR-NOTIF)

- **FR-NOTIF-1 (In-App Центр уведомлений)**:
  - Верхний колокольчик со счетчиком непрочитанных критических событий.
  - Боковая панель со списком активных угроз, возможностью быстрой фильтрации и перехода к карточке проблемного проекта/договора.
- **FR-NOTIF-2 (Telegram-бот)**:
  - Мгновенная отправка сообщения при обнаружении `CRITICAL` риска после парсинга нового файла.
  - Ежедневный утренний дайджест (по расписанию компании, например, в 08:30) с краткой сводкой дня (деньги, горящие дедлайны).
  - Интерактивные кнопки под сообщением: «Просмотреть детали», «Отметить решенным».
- **FR-NOTIF-3 (Журнал доставки)**:
  - Логирование фактов отправки сообщений в Telegram (статус доставки, ошибки, время).

## 3. Матрица трассируемости (Traceability Matrix)

| Требование | Бизнес-цель | Сущность БД | Ключевые API эндпоинты |
| :--- | :--- | :--- | :--- |
| **FR-AUTH-1..4** | Безопасность и изоляция данных | `companies`, `users` | `/api/v1/auth/*`, `/api/v1/companies/*` |
| **FR-INGEST-1..5** | Прием файлов без предварительной подготовки | `uploaded_files` | `/api/v1/files/upload`, `/api/v1/files` |
| **FR-PARSE-1..4** | Умное извлечение бизнес-метрик из Excel | `file_templates`, `parsing_jobs` | `/api/v1/files/{id}/process` |
| **FR-PREVIEW-1..3** | Прозрачность и доверие к данным (UI) | `file_templates` | `/api/v1/files/{id}/mapping-preview`, `confirm` |
| **FR-DASH-1..5** | Экран первого взгляда для собственника | `tender_projects`, `cashflow_operations`, `payroll_records`, `operational_tasks` | `/api/v1/dashboard/*` |
| **FR-ALERT-1..4** | Предотвращение штрафов и убытков | `system_alerts` | `/api/v1/alerts/*` |
| **FR-NOTIF-1..3** | Оперативная реакция без захода в систему | `notification_logs`, `integration_settings` | `/api/v1/notifications/*`, `/api/v1/telegram/*` |
