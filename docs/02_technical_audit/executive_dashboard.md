# Панель руководителя и обзор TEP Dashboard

## Сценарий выпуска

Директор и заместитель открывают общий обзор, выбирают сигнал, смотрят карточки записей и при необходимости переходят в Google Таблицу. Сотрудники продолжают вести исходный документ на Google Диске. Платформа читает существующий фиксированный шаблон через Google Drive и связывает листы по внутреннему номеру.

Рабочие разделы и их назначение перечислены в [README](../../README.md#рабочее-пространство-руководителя). Импорт реестра питает обзор, контракты и мониторинг. Остальные модули используют свои API и показывают пустые состояния, пока нет соответствующих данных.

Просроченный срок и срок на горизонте до трёх дней попадают в критическую группу. Предупреждение охватывает следующие четыре дня. Календарь использует часовой пояс Астрахани. Правило берёт дату из поля «Срок исполнения (акты)». Для завершённых и отменённых контрактов сигнал закрыт. Если в мониторинге заполнено несколько периодов, одна дата реестра не позволяет связать срок с конкретным периодом. При наличии отметки о работах без отметки о документах карточка предлагает сверить источник. Поля выставления, ссылки, размещения и подписания служат признаками документирования. Сигналы показывают состояние данных, по которому руководитель может проверить исходник.

Организация папок по процессам подходит для ручной навигации сотрудников, например «Тендеры и контракты», «Исполнение и документы», «Архив». Текущий документ объединяет два процесса и остаётся целым. Импорт выбирает его по настроенному ID. Для каждого дополнительного документа потребуется сверить структуру, правила сопоставления и границы доступа.

Ранние PRD, SQL и OpenAPI в соседних каталогах описывают расширенный продукт. Директор работает через один вход с правами операционного руководителя. Прежние модули доступны из общей навигации. Статусы меняются в базе платформы, а связанная Google Таблица остаётся источником импортируемых полей.

## Публичные исходники конкурента

Проверена ветка main на коммите [03f86df](https://github.com/Khinskii/tep-dashboard/tree/03f86df). Размещённая страница GitHub Pages была недоступна для проверки через браузинг. Выводы ниже основаны на публичном коде.

| Раздел TEP | Вопрос руководителя | Применение у нас |
| --- | --- | --- |
| Обзор и корреспонденция | Где просрочили и что требует внимания? | Карточки сигналов открывают записи с соответствующим фильтром |
| Финансы и БДДС | Как меняются остатки, поступления и выплаты? | Отдельный будущий источник для денежных операций |
| Производство | Какие объекты отстают и на какой стадии работы? | Статус и срок из реестра, связанные с мониторингом |
| Табель и ФОТ | Где расхождения в начислениях и выплатах? | Отдельный будущий источник с разграничением кадровых данных |
| Штат и охрана труда | По каким сотрудникам нужно проверить допуски? | Отдельный сценарий при наличии согласованного шаблона |
| ПТО и закрытие документов | На каком этапе акты и что ещё нужно закрыть? | Проверка документирования и переход к исходной строке |

В [index.html](https://github.com/Khinskii/tep-dashboard/blob/03f86df/index.html) клиент обращается к /api/check-access, /api/data и /api/refresh. Для первых двух есть резервное чтение статических JSON. В [server.py](https://github.com/Khinskii/tep-dashboard/blob/03f86df/server.py) обработчик обновления вызывает извлечение данных. [sync_service.py](https://github.com/Khinskii/tep-dashboard/blob/03f86df/sync_service.py) выгружает настроенные документы Google Drive и извлекает значения через openpyxl в JSON-снимок. В каталоге [api](https://github.com/Khinskii/tep-dashboard/tree/03f86df/api) лежат обработчики Vercel для доступа и чтения данных. Эти маршруты описывают исходники, а доступность на GitHub Pages отдельно не подтверждена.
