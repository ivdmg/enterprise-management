# Технический аудит и оценка качества репозитория `Khinskii/tep-dashboard`

В данном документе приводится глубокий технический разбор архитектуры, кодовой базы, механизмов парсинга, безопасности и ИИ-функционала репозитория [Khinskii/tep-dashboard](https://github.com/Khinskii/tep-dashboard).

---

## 1. Общая характеристика проекта

- **Назначение**: Прототип веб-дашборда для мониторинга финансово-производственных показателей строительно-монтажного предприятия (ООО «ТЭП» / МПБ).
- **Стек технологий**:
  - *Бэкенд*: Python 3 (стандартные библиотеки `http.server`, `socketserver`, `threading`, внешняя библиотека `openpyxl`).
  - *Интеграция*: Google Drive API (`google-api-python-client`).
  - *Фронтенд*: Монолитный HTML/JS с Tailwind CSS (CDN), Chart.js (CDN), Lucide Icons (CDN).
  - *Хранение*: Локальный JSON-файл кэша (`live_data.json`).
  - *Деплой*: Конфигурация `vercel.json` и локальный HTTP-сервер на порту 8088.

## 3. Детальная оценка ключевых подсистем

### 3.1. Механизм парсинга Excel и интеграция данных (Sync Service)
- **Как устроено**:
  В файле `sync_service.py` функция `extract_all()` подключается к Google Drive, скачивает таблицы по жестко заданным Google File ID (например, `1VbPX7uS0yN-21UBOpmQ3dXsuVW-UgjzihswbjNwc8Jo`) в формате `.xlsx` и читает данные через `openpyxl`.
- **Критические проблемы**:
  1. **Абсолютный хардкод ячеек**:
     ```python
     # Пример из sync_service.py:
     mpb_start_plan = to_float(ws.cell(6, 4).value)
     mpb_start_fact = to_float(ws.cell(6, 5).value)
     mpb_net_plan   = to_float(ws.cell(7, 4).value)
     ```
     Если пользователь вставит пустую строку сверху или добавит столбец, вся логика сбора данных сломается без предупреждения.
  2. **Хардкод имен листов**: Код жестко завязан на названия листов `"Лист1"`, `"всего оплачено"`, `"Реестр сотрудников"`.
  3. **Частичный мок-хардкод**: Раздел «Производство (Объекты 100-103)» полностью зашит в коде статическим словарем (строки 134–181 в `sync_service.py`), то есть реальный парсинг для производства даже не реализован.

### 3.2. Архитектура и качество кода (Code Quality)
- **Оценка**: **3 из 10** (Уровень быстрого proof-of-concept / хакатонного скрипта).
- **Ключевые проблемы**:
  1. **Антипаттерн генерации HTML через Python-скрипты**:
     Вместо шаблонизаторов (Jinja2) или компонентного фронтенда (React/Vue/Svelte/Vanilla Web Components), разметка на 1200+ строк вшита прямо в Python-переменную `html_content = '''...'''` в файле `generate_dashboard.py`, а затем дорабатывается скриптами `patch_html_live.py` и `update_with_personal_agent.py` через методы `content.replace("</body>", ...)`. Это делает проект крайне хрупким и нечитаемым.
  2. **Захардкоженные абсолютные пути MacOS**:
     По всему коду разбросаны пути вида:
     `/Users/user/.gemini/antigravity/scratch/tep_dashboard/live_data.json` и `/Users/user/ai_agent`.
     На другой операционной системе (Windows/Linux) или у другого пользователя проект не запустится без правки десятков строк.
  3. **Отсутствие модульности и типизации**: Нет классов, dataclass или pydantic-схем для валидации бизнес-сущностей.

### 3.3. Оценка ИИ-составляющей (AI Personal Agent)
- **Оценка**: **Имитация (Mock UI)**.
- **Разбор**:
  - В интерфейсе присутствует красивый плавающий виджет «Личный агент руководителя» с переключателем «Корпоративный / Личный помощник».
  - Однако, заглянув в `update_with_personal_agent.py`, мы видим, что кнопкам назначены статичные заготовленные текстовые шаблоны (`drawerPresetResponses`):
    ```javascript
    const drawerPresetResponses = {
      mail: `<b>✉️ Проверка входящих писем (Apple Mail & Gmail):</b>...`,
      whatsapp: `<b>💬 Автономная отправка сообщения в WhatsApp:</b>...`,
      report: `<b>📄 Генерация Word-документа:</b>...`
    };
    ```
  - Никакой реальной LLM-модели (OpenAI, Anthropic, DeepSeek, локальной Ollama/Llama) к бэкенду не подключено.

### 3.4. Безопасность и надежность (Security & Reliability)
- **Оценка**: **Критически низкая (2 из 10)**.
- **Уязвимости**:
  1. **Примитивная аутентификация**: Авторизация построена на совпадении 4-значного PIN-кода из открытого JSON (`demo_config.json`).
  2. **Отсутствие сессий и токенов**: Защищенные данные легко перехватить; нет JWT, cookies, защиты от подделки запросов (CSRF).
  3. **Полный доступ к CORS (`*`)** без фильтрации origins.
  4. **Синхронный блокирующий ввод-вывод**: Ошибки в Google API роняют фоновый поток или приводят к зависанию сервера.

### 3.5. UX/UI и визуальный дизайн
- **Оценка**: **8.5 из 10 (Сильная сторона проекта)**.
- **Плюсы**:
  - Прекрасно подобранная цветовая гамма: стильный темный фон (`#0B1120`), карточки с мягкой границей (`#202E46`), неоновые акценты (циановый, изумрудный, янтарный).
  - Наглядное разделение на смысловые блоки: Финансы, Производственные объекты, Реестр сотрудников, Горящие поручения.
  - Качественные микроанимации: пульсирующие бейджи статусов, удобный дровер ассистента.

## 5. Что следует перенять и что сделать иначе в нашем проекте

### Что взять как ориентир:
- **Премиальный визуальный стиль**: темная тема, четкие KPI-карточки, цветовая индикация рисков (зеленый/желтый/красный), плавающий ассистент.
- **Бизнес-фокус на конкретные боли руководителя**: отдельный акцент на срывы графиков, остатки по контрактам, долги по ФОТ и налогам.

### Что полностью переделать и спроектировать с нуля:
1. **Универсальный парсер Excel**: гибридный конвейер (эвристический анализ структуры + быстрый LLM-маппинг столбцов).
2. **Чистая архитектура**: FastAPI / легкий Node.js бэкенд + нормальная компонентная структура фронтенда.
3. **Multi-tenancy (Мультиарендность)**: регистрация компаний, изолированные личные кабинеты, роли пользователей.
4. **Настоящий ИИ-ассистент**: подключение сверхдешевых и эффективных моделей (DeepSeek / Gemini Flash / локальные модели) с контекстом загруженных документов.
5. **Полноценная система алертов**: генерация триггеров на основе дат и сумм с уведомлениями в Telegram и браузер.
